## Что потребуется от владельца

Подключённый GitHub-инструмент не умеет создавать репозитории и управлять Pages. Эти настройки нужно выполнить самостоятельно. Токены и пароли присылать не нужно. Удобнее сделать это с компьютера, программирование не требуется.

1. Скачайте из Lite/Delivery/ файл **FinRate_Lite_GitHub_Pages_test01.zip** и распакуйте. Внутри девять файлов, включая .nojekyll. Не используйте ZIP всей ветки: в нём есть Full и исходники, а для сайта нужны только девять файлов сборки.
2. Откройте https://github.com/new. Владелец kqh2rnnnmm-dot, имя **finrate-lite-test**, видимость **Public**, включите Add a README file и нажмите Create repository. Не используйте имя kqh2rnnnmm-dot.github.io: это корневой сайт владельца.
3. В новом репозитории нажмите Add file → Upload files. Загрузите содержимое распакованного архива в корень: index.html должен находиться рядом с README, без вложенной папки. Нажмите Commit changes. Если .nojekyll скрыт системой, создайте его через Add file → Create new file, имя .nojekyll, содержимое можно оставить пустым, затем Commit changes.
4. Только в **новом finrate-lite-test** откройте Settings → Pages. Source: **Deploy from a branch**, Branch: **main**, Folder: **/(root)** → Save. Не выбирайте собственный workflow GitHub Actions и не меняйте Pages в существующем finrate.
5. Дождитесь, пока GitHub покажет ссылку опубликованного сайта. Ожидаемый адрес при этих имени/владельце: https://kqh2rnnnmm-dot.github.io/finrate-lite-test/ . До завершения публикации это лишь ожидаемый адрес, а не проверенная работающая ссылка. Откройте именно ссылку из Pages. Enforce HTTPS должен быть включён.
6. Отправьте мне фактическую ссылку для проверки HTTPS, MIME, ресурсов и offline. В этой передаче новый сайт ещё не опубликован и не проверен.

## Почему не тратится квота вычислений

Служебный запуск Pages может отображаться во вкладке Actions даже при Deploy from a branch и .nojekyll. Файл .nojekyll отключает Jekyll, но не служебную доставку сайта. По документации GitHub стандартные runners для Pages бесплатны; стандартные runners публичных репозиториев также не уменьшают включённую квоту вычислений. Здесь не используются larger runners, собственные workflows, npm-сборка, Actions cache и пользовательские Actions artifacts.

Это не означает отсутствие всех ограничений GitHub: у Pages остаются собственные лимиты. Не включайте платные runners или сторонние CI ради этой сборки.

Официальные источники:
- https://docs.github.com/en/billing/concepts/product-billing/github-actions
- https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site

## Изоляция от Full

Разные репозитории Pages одного владельца имеют общий origin github.io. Новый путь сам по себе не изолирует IndexedDB. Lite уже использует собственные DB, BroadcastChannel, manifest ID и кеши; SW Lite ограничен его каталогом. В исследованном Full SW регистрируется относительным ./sw.js, то есть обычный /finrate/ не должен контролировать соседний /finrate-lite-test/.

Но неизвестную прежнюю регистрацию SW в корне origin нельзя исключить по исходникам. Самый строгий вариант — отдельный HTTPS-домен для Lite, если он у вас есть. До использования данных проверьте фактический сайт и отсутствие контроля корневым SW. Не очищайте данные Full ради запуска Lite. При неожиданном интерфейсе Full остановитесь и сообщите URL.
