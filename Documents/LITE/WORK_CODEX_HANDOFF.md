# FinRate Lite — готовое поручение Work / Codex

Статус: шаблон для будущей передачи после восстановления лимитов. НЕ разрешает код/merge/deploy сам по себе.

## Передача в Work — сначала анализ, UX и план (можно переслать целиком)

Работаем над отдельным продуктом FinRate Lite, не заменяя и не меняя существующий FinRate Full. Репозиторий: https://github.com/kqh2rnnnmm-dot/finrate

Прочитай в ветке lite/spec-v0.1-2026-11-13 главный документ:
Documents/LITE/FINRATE_LITE_SPEC_v0.1_2026-11-13.md

Также проверь актуальный main, Documents/03_CHECKPOINT.md, Documents/02_DECISIONS.md, DESIGN.md, Documents/09_UX_SPEC_v0.1.md, Documents/12_UI_BEHAVIOR_CONTRACT_v0.1.md, Source/MODULE_MAP.md и только нужные файлы Source/. Последние прямые решения владельца имеют приоритет.

Задача:
1. Сверь утверждённые продуктовые правила Lite с реальной архитектурой, источниками финансовых фактов, шифрованием и UX Full.
2. Подготовь финансовую матрицу: месяц, несколько доходов, согласие «Да/Нет» на распределение, отклонённое распределение, 0%-конверты, ручное распределение суммами, расход без категории, protected savings/investment, возврат из защиты, переход месяца и редактирование с расходами.
3. Зафиксируй конфликтующие трактовки и только критически важные ещё не утверждённые вопросы. Не выдавай предложения за утверждения.
4. Покажи интерактивный образец ПРЯМО в чате, а не ссылкой и не кодом, в существующей системе FinRate. Главная/Конверты/Отчёты только сверху, onboarding отдельно от повседневных настроек.
5. Особое внимание: live-перетекание денег при движении ползунка и контекстное окно НАД изменяемой карточкой ПОСЛЕ нажатия «Сохранить» с двумя короткими выборами и «?». Не использовать bottom sheet как нормальный вариант.
6. Подготовь экономный модульный план Lite как отдельного продукта, с общими проверенными блоками для Full/MyRate и проверкой переноса данных.
7. НЕ писать код, НЕ создавать релиз и НЕ менять main, GitHub Pages или настройки пользователя. Отдельное согласие владельца нужно перед программированием.
8. GitHub Actions отключены; не запускать. Не использовать реальные финансовые данные в тестах.

Результат: краткий обзор, проверенная финансовая матрица, интерактивный макет прямо в чате, список открытых вопросов, план отдельных PATCH с критериями приёмки.

## Передача в Codex — только ПОСЛЕ отдельного разрешения владельца на код

Я отдельно разрешаю начать программирование FinRate Lite согласно утверждённой версии Documents/LITE/FINRATE_LITE_SPEC_v0.1_2026-11-13.md и дополнительно согласованным ответам на открытые вопросы. Не менять FinRate Full/main. Работать в отдельной реализационной ветке от проверенного актуального SHA. Сначала тесты RED для финансовых событий, затем минимальная реализация GREEN и регресс. Перед работой найти реальные владельцы модулей, структуру Source и действующие команды; не переписывать все файлы. Включить UI-конфигурацию Lite без появления скрытых Full-функций в меню и FAQ, безопасность, локальный backup и точные суммы. Проверить double-tap, атомарность, месяц, UX popover над карточкой, live-расчёт, ручное перераспределение, сохранение истории и iPhone safe-area. Статусы проверить фактически, PASS не придумывать. GitHub Actions не запускать. Подготовить PR без merge/deploy, отчёт о тестах, пакет файлов/изменений, контрольные точки и инструкции аппаратной проверки. После PR остановиться и запросить приёмку.

ВАЖНО: эту вторую часть разрешается пересылать только когда владелец действительно дал новое прямое согласие программировать. Она не считается данным сейчас разрешением.
