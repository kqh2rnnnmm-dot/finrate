# FinRate Lite — контракт реализации 0.1.0

Приоритет: IMPLEMENTATION_TASK.md (прямое разрешение на L1–L5 и политики раздела 5) выше исторических запретов reference. Base main: 13d585c636918e4b25b717b2bd35c85d469d94a0. Ветка codex/finrate-lite-test-v0.1; изменения только Lite/ и Documents/LITE/.

Факты и назначения хранятся в одном зашифрованном документе product=finrate-lite/schema=1. Денежные суммы — целые копейки с ограничением безопасного диапазона; доля каждого дохода считается BigInt и округляется вниз независимо. Начальный остаток не доход. F = остаток + доходы − расходы + связанные возвраты. A = F − P. Назначения и защита не увеличивают F.

Журнал упорядочен по date, seq, id. События income хранят snapshot процентов и ответ allocate; только allocate=true входит в auto-базу. Изменения процента — отдельные события plan. Расход/защита сначала поглощают auto, затем неавтоматические назначения. usedAuto хранится в расчётном состоянии и не уменьшается при снижении процента; свободный auto = max(0, сумма floor(каждый доход × новый процент /100) − usedAuto). Ненулевой процент сохраняет прочие назначения. При переходе к 0% свободный остаток переходит в нераспределённые; usedAuto/факт/защита сохраняются. Повторное включение не восстанавливает освобождённые ручные назначения. Сохранение неизменённого 0% не освобождает свежий возврат.

Обеспеченный свободный предел = max(0,min(новые+старые нераспределённые, A − сумма положительных свободных конвертов)). Это учитывает отрицательные планы. Ручное назначение и защита проверяют источник и этот общий предел. Обычный расход сверх плана разрешён при n≤A, показывается отрицательный бюджет. Нельзя расходовать P или скрыто занимать.

Возврат покупки — событие со ссылкой purchase, датой получения, историческим конвертом исходной покупки. Ограничен её невозвращённой суммой, не доход и не auto-база. Неавтоматический остаток доступен при 0%; освобождение отдельной командой releaseFree. Возврат защиты — в новые нераспределённые, не доход. Отчёт чистого накопления = взносы − возвраты защиты.

Новый месяц переносит A в старый остаток ровно один раз, не копирует конверты, использует действовавший шаблон future. Постоянный шаблон изменяется отдельным событием template без пересчёта текущего auto. Месяц+future записываются одним документом. Историческое исправление хранит before/ревизию в edits и переигрывает историю. F<P отклоняется без снятия защиты. Отменённое событие остаётся в истории и не влияет на расчёт; связанные возвраты не могут стать бесхозными.

Category parent имеет конверт, ребёнок наследует. Расход сохраняет собственный envelope snapshot. Перепривязка справочника не переносит прошлые расходы. Архив сохраняет ID и историю; требует нулевого текущего и будущего процента, разрешённых остатков/категорий.

Preview клонирует документ в RAM, не пишет. Ошибка валидации/шифрования/IDB/CAS не меняет активный документ. Устойчивый event ID исключает повтор события; другой payload того же ID отклоняется. Сохранение: validate → seal → compare-and-swap transaction → обновление RAM. Квота прерывает транзакцию. Настройки шага сохраняются отдельно от preview, не округляют проценты.

Криптография/хранение/PIN адаптированы из Source/src/crypto.mjs, store.mjs, device-access.mjs: AES-GCM, PBKDF2-SHA256 600000, password/recovery slots; алгоритмы сохранены. Маркеры Lite и валидатор заменены адресно. DB finrate-lite-local-v1; BroadcastChannel finrate-lite-v1; manifest id ./finrate-lite; кеш finrate-lite-<hash>. Нужен отдельный origin из-за возможного корневого SW Full. Копии finrate-lite-backup/1 не совместимы с Full: фактический parseBackup Full отклоняет маркер.

Физическую сохранность браузерного хранилища не гарантируем; внешняя проверенная защищённая копия обязательна. Кодовый откат не восстанавливает данные. Подробная лотовая аудиторская ведомость не является отдельным экраном: происхождение восстанавливается из событий/ревизий; пользовательский отчёт агрегирует auto/прочее.
