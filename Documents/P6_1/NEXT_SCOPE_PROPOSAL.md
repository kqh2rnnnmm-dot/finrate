## Что должен получить человек
Открывает существующую нижнюю вкладку **«Отчёты»** и без лишних нажатий видит **за текущий месяц**: сколько фактически получено, потрачено и каков результат периода. Нажимает на «Расходы» → видит основные категории с понятными соотношениями/наглядными полосами → выбирает категорию → видит прямые траты по родителю и подкатегории → выбирает подкатегорию → видит реальные операции → карточка → «Назад» возвращает в прежний список с периодом/фильтрами/позицией. Без дублирования исходного расхода и без «мелкой числовой бухгалтерии» в первом экране. Прогноз, реализованный в P5, остаётся доступен из «Отчётов», не переписывается.

## Состав P6.1
1. **Стартовый обзор:** текущий месяц по умолчанию, выбор другого календарного периода; три главных значения «Доходы», «Расходы», «Результат периода = фактические доходы − фактические расходы». Результат не тождественен изменению общего остатка; при необходимости короткая расшифровка почему.
2. **Состав расходов:** группировка по основной категории и подкатегории с точным учётом allocation каждой фактической операции/внутренней комиссии/покупок; прямые расходы основной категории остаются отдельной строкой внутри неё. Не суммировать основной category total повторно поверх children. Аналогично доступна расшифровка доходов.
3. **Возвраты и исправления:** чистый расход уменьшается в периоде фактического возврата по прежней финансовой модели, не обычный доход. Отмены, исправления и разделённые покупки не образуют новых фактов. Переводы между своими счетами, выдача/возврат тела долга, пересчёт начального остатка, выделение/освобождение резервов не считаются доходом/расходом. Кредитный лимит и неиспользованный кредит — не собственный доход.
4. **Навигация:** существующие панели/списки/карточки с правилами Back; выбор периода, раскрытый раздел, фильтры и scroll сохраняются при переходе к операции и обратно. Период для «Отчётов» не перезаписывает пять сохранённых режимов «Свободных денег» B1/P5.
5. **Сравнение периодов** только по запросу, а не постоянная таблица на входе; различать полный и неполный период/неподтверждённые данные. Не выдавать сравнение нескольких валют как одну конвертированную сумму без существующего проверенного расчёта.
6. **Вспомогательные блоки** по существующим данным (остатки, долги/обязательства, резервы/цели, лимиты) кратко, без второго учёта фактов, с адресным переходом в штатную карточку. Не превращать старт «Отчётов» в большую прокручиваемую ленту чисел.
7. **UI:** использовать утверждённые токены/три визуальные стилистики имеющихся сводок и компоненты FinRate, не изобретать глобальные темы, шестую вкладку или новый редизайн. Читаемые наглядные состояния/полосы, а не избыточные проценты/спарклайны; 320–430 CSS px, iPhone safe-area, desktop адаптация, светлая/тёмная темы. Нет обычного вертикального скролла на Главной, у отчётного списка своя разрешённая прокрутка. Не привязывать новое содержимое к Apple/облаку.
8. **Никаких небезопасных операций:** P6.1 исключительно чтение и проекции. Нет новых полей `SCHEMA=5`, миграций, записей в IndexedDB, автоматической синхронизации и изменения `finrate-backup/1`. Длинные суммы сохраняют точность копейки и однострочную подачу. Пустые состояния понятны.

- Автоматическая импорт/синхронизация банков, облака, OCR, Apple Account, Face ID, пассключи, сервер, PDF без отдельного согласия.
- Новые кредитные проводки, «универсальная» перепись `model.mjs`/B1; любые новые отчётные правила, противоречащие каноническим `totals` и операциям.
- Не реализовывать отдельную неподтверждённую функцию накоплений или новый пользовательский график цели.
