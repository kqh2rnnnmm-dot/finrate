# P1.2 — аудит основы

Фактический main `4ac42ea024d5676a0e0d076b235b90b57d4f970c`, PR9 объединён, p1-1-payments01/0.3.10-p1.1. Исторические «PR открыт» и «решение переменной суммы ожидается» больше не действуют: владелец утвердил полную/частичную оплату 05.11.2026. A2/A3/P1.1 не прошли аппаратную проверку.

P1.1 уже имеет детерминированный календарь, snapshots/links, shared expense editor, forecast expense seam, single service/CAS transaction, A2 cleanup и защищённые копии. Их используем повторно. Нет batch/calendar/moves/month skip/bank outcomes. Дефект переменной суммы: остаток всегда estimate−active expenses и validator запрещает превышение; флага финального факта нет.

Совместимое расширение только optional полей payments/version1. Закрытие связывается с расходом (final в link), не независимая необратимая отметка. Отмена final повторно открывает оценку, сохраняя другие части. Перенос хранит отдельную dueDate, ID остаётся по исходной дате; skip запрещён при любом активном частичном факте. Оплаченная история не заменяется новым расписанием. Массовая запись — одна service.mutate/IDB commit; промежуточные расходы видны только внутри частной копии.

Хранение/шифрование/ключи/SCHEMA5/backup1 не меняются. Старые документы читаются без записи миграции. Старый P1.1 не понимает новые опциональные поля и не является безопасным runtime downgrade: сохранять внешнюю копию до P1.2, не сбрасывать автоматически. SHA всех модулей основы зафиксированы в Source/P1_2_MAIN_BASELINE_SHA256.json.

## Совместимость и защита

Нет миграции при старте или запросах. `SCHEMA=5`, `payments.version=1`, `finrate-backup/1`, IDB, DEK/слоты и ключи остаются прежними. Новые optional поля: links.final; occurrences.dueDate/skipped/bankResult/history; plans.history. Канонические суммы и реальные даты/счета существуют только в operations. Переменный total за период — сумма активных связанных фактов; независимой окончательной суммы долга и необратимого флага закрытия нет.

Если final отменяется, остаются остальные части; инвариант суммы частичных фактов ниже оценки гарантирует положительный известный остаток. Превышение оценки частями требует явного уточнения, а не автоматического увеличения. При старой закрытой истории временное преобразование inferred final выполняется только в атомарной явной правке пользователя. Суммы/счета будущего шаблона не переписываются из факта.

Forward compatibility проверяется с настоящим экспортом точной P1.1-сборки и её service-worker обновлением: ciphertext не меняется при запуске P1.2, старый файл восстанавливается в отдельном профиле. Новые данные P1.2 не заявлены совместимыми с runtime P1.1: старый strict validator не знает optional полей и может безопасно отказать. Точка отката кода — `4ac42ea`; возврат состояния требует собственной внешней копии до первого изменения P1.2. Ветка backup/pre-p1-1-main-2026-11-05 относится к ещё более старой A3-основе, не к откату P1.2.

`model`, `operations`, `planning`, `recurring-income`, `credit`, `block02`, `service`, `store`, `crypto`, `device-access`, `reset-policy/reset-ui`, навигация/поверхности/редактор поля и уведомления защищены SHA исходного main. Единственные runtime-изменения: scheduled-payments, payments-ui, узкие ветви focus, сообщения/build в app, FAQ и scoped calendar CSS. Старые стили/палитры идентичны.

Границы доверия: ввод/импорт копии → строгая проверка known fields/дат/ссылок/лимитов; вывод имён → HTML encoding; подтверждение → private copy + прежние B1 проверки + единый seal/CAS; квота/конфликт → прежняя запись. Секреты/файлы копий/дампы не включаются в артефакты. Банковской интеграции нет.


Бессрочная пауза применяется и к неоплаченным будущим overrides: родительская пауза вычисляется по исходной и эффективной дате, не хранится как новый финансовый факт. Если срок уже возник или есть действующая часть, остаток остаётся. При возобновлении не возвращаются пропущенные во время паузы даты. Для приостановленного родительским планом экземпляра UI явно предлагает возобновить платежи плана, не маскирует это как одну месячную отмену.
