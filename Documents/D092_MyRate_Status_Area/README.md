# D-092 · проверка системной верхней области по MyRate

Дата: 11.11.2026. Статус: **кандидат для аппаратной проверки, НЕ закрыт**. Только отдельная ветка, без `main`, публикации Pages, включения Actions или изменения пользовательских финансовых данных.

## Источники

- **MyRate** (`kqh2rnnnmm-dot/my-rate@main`): `index.html` содержит `viewport-fit=cover`, standalone и `apple-mobile-web-app-status-bar-style=default`. В `styles.css` `html` и `body` имеют общий `background:var(--bg)`; safe-area inset применяется как отступ страницы. Отдельного CSS-псевдоэлемента для статуса нет.
- **FinRate** (`kqh2rnnnmm-dot/finrate@main`): `Source/src/index.html` также использует `viewport-fit=cover`, но не задаёт статусный стиль — это эквивалентно `default` в документации Apple. `Source/src/style.css` дополнительно рисует `#app::before,.sheet.large::before` фиксированным tint + blur + mask над safe-area; при уменьшении прозрачности полоса получает сплошной canvas. В `Source/src/color-theme.css` есть отдельная окраска того же псевдоэлемента.
- История `Documents/09_UX_SPEC_v0.1.md`: D-092 уже получал аппаратный FAIL, CSS-попытка R21 не была подтверждена на iPhone.
- Apple: `apple-mobile-web-app-status-bar-style` со значением default или без meta отображает нативную системную строку. WebKit issue 317153 (комментарий разработчика от 16.06.2026) сообщает об ограничениях отрисовки под системным статусом iOS и об устаревании `black-translucent`. Переход на него не предлагается.
  - https://developer.apple.com/library/archive/documentation/AppleApplications/Reference/SafariHTMLRef/Articles/MetaTags.html
  - https://bugs.webkit.org/show_bug.cgi?id=317153

## Гипотеза и правка

Основное отличие, которое мы можем безопасно перенести из MyRate: верхняя системная область **не имеет отдельной искусственной фиксированной подложки**. На узких экранах и устройствах с грубым указателем:
1. Явно красим `#app` в тот же `var(--canvas)`, который уже используется у html/body, включая светлую/тёмную/цветную палитру.
2. Отключаем созданные для системной строки `#app::before` и `.sheet.large::before` через `content:none`.
3. Не меняем viewport meta, геометрию фиксированных островов, safe-area, модели, JS, уведомления, криптографию и базу. Не вводим `black-translucent`, так как это может усугубить геометрию iOS.

Это убирает **собственную** глухую/тонированную полосу FinRate. Нельзя обещать физическое удаление **нативной** зоны часов: её отрисовкой владеет iOS. Результат может быть лишь визуальным совпадением фона с MyRate.

## Приёмка на настоящем iPhone

1. Вначале сделать проверенную защищённую копию данных FinRate; резервная ветка GitHub **не** сохраняет финансовую базу.
2. После отдельного согласия на merge и сборку открыть обновлённое установленное FinRate **без удаления и повторной установки PWA**.
3. Сравнить полосу часов/сети/батареи и фон непосредственно ниже неё с MyRate: нет резкого прямоугольника над плавающим островом.
4. Проверить светлую и тёмную темы, нейтральную и цветную палитры, обе крупные суммы, меню, модальное окно, быстрый ввод, поворот iPhone.
5. Проверить, не попадают ли кнопки под Dynamic Island/часы, что прокрутка и нижняя панель не изменились.
6. Если системная зона осталась сплошной, но в цвет фона — считать CSS улучшение частичным; **D-092 закрывать только при подтверждении владельцем визуального результата**. Не обещать нативное размытие WebKit.
