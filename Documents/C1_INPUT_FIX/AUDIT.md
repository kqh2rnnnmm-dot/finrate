# Корректирующий C1: адресная диагностика и системный UI/UX-аудит

База: main `4d3eccf143fd4644bfed46fbc655f00424b959bb` (C1 объединён владельцем). Предыдущая контрольная точка с незалитым PR №1 сохранена как история, но больше не описывает текущий main. Эта корректировка находится только в отдельной ветке, не опубликована.

## Доказанные причины и изменения

1. **Просвечивание вложенного экрана — воспроизведено.** `.sheet.large::backdrop` был transparent. Полноэкранная поверхность ограничена VisualViewport; вне её прямоугольника виден основной экран. Корневой #app скрывался только при `focus-mode` операций. Ввод суммы планируемого дохода использовал тот же field-editor без focus-mode, поэтому показывал настройки под собой. До: backdrop rgba(0,0,0,0), root visibility visible; после: непрозрачный цвет существующего canvas, root hidden. Общий стек surfaces вычисляет screen-surface-open по всем сохранённым large-поверхностям; inert и возврат скролла сохранены. Compact/context overlays не превращались в fullscreen.
2. **CSS фокусировки менял геометрию — воспроизведено.** Группа `.field-editor .field-input:focus` имела большую специфичность, чем правило scalar input, и переопределяла `flex:0` на `flex:1`. Поле суммы растягивалось на всю высоту формы. Правила состояния больше не повторяют структурную раскладку; одноcтрочное поле остаётся одноcтрочным.
3. **Редактор длинного текста — подтверждены хрупкие структурные правила, но маленькое поле iPhone полностью не воспроизведено.** Старый flex-контейнер использовал `height:100%` внутри flex-области с padding; textarea полагалась на intrinsic/flex-размеры. В Chromium и WebKit/Linux при нашей модели высоты он занимал большую часть доступной формы. Точное поведение IMG_2646 на нативной клавиатуре iOS не подтверждено. Устранена зависимость от этой комбинации: sheet-body получает определённый grid-трек, note form — minmax(0,1fr) + auto для счётчика, textarea — единственная вертикальная прокрутка. На уменьшение высоты текстовая область реагирует непосредственно. Это требует повторной аппаратной проверки, а не объявления дефекта iPhone закрытым автоматически.
4. **Конкурирующие владельцы прокрутки.** Общий keepInputVisible мог двигать внешнюю sheet-body для большого textarea, а chrome выбирает scrollable sheet-body и резервирует место под свои стрелки. В field-editor внешний скролл отключён; textarea сама обслуживает каретку. Chrome не создаёт стрелки/резервирование в редакторе поля. Стрелки существующих списков/выборов сохранены.
5. **Скрытие клавиатуры и потеря фокуса.** Старый updateViewport вызывал blur для любого редактора при переходе keyboard-open → closed. Теперь текстовое поле не теряет фокус от одного лишь изменения viewport (в том числе поворота). Скрытие через пользовательский fallback вызывает только blur, не apply. Сохранение/dirty guard прежние. Числовое завершение и отдельное финансовое подтверждение не менялись.

## Панель над клавиатурой

В коде нет созданной FinRate панели «предыдущее поле / следующее поле / галочка». Есть верхние Готово/Сохранить и отдельные существующие стрелки списков. Системные inputmode/enterKeyHint оставлены. Скриншоты IMG_2646/IMG_2647 не были доступны среди вложений текущей среды; поэтому происхождение именно изображённой панели визуально не удостоверено. Нативную accessory-панель iOS не скрывали нестандартными приёмами. Наши стрелки списков исключены из field-editor.

## Охват и геометрия

| Область | Общий компонент / покрытие | Статус |
|---|---|---|
| Суммы расхода/дохода/перевода/комиссии/погашения/разделения/кредитных частей | focus.textValue / enhancer → field-editor; forms/unified/credit | Общая исправленная раскладка, финансовые обработчики прежние |
| Операционные/refund/draft note | field-editor/open/view, focus.advanced | Один текстовый scroller, чтение отдельно, guard сохранён |
| Счёт: имя/note, категории/подкатегории | enhancer / management / inline creation | Наследуют исправление без отдельных локальных редакторов |
| План: сумма/название/comment, включая закрытое поступление | planning-ui → focus.textValue/enhancer | Прямая регрессия вложенной суммы; прочие вызовы общего механизма сохранены |
| Кредитные формы | credit-ui + enhancer; policy/allocations прежние | Изолированная large-поверхность, финансовые поля/лимиты прежние |
| Настройки и безопасность | Выборы, переключатели и security inputs | Новых длинных текстовых полей не обнаружено; PIN/password не перехватываются enhancer; large изоляция общая |
| Списки, карточки, FAQ, история | Существующие main/sheet-body, typography/money components | Release regression и прежние tokens; локальный редизайн не проводился |

Отступы: сохранены --page-gutter, --island-gutter и остров заголовка; gap редактора переведён на --peer-gap. Счётчик остаётся штатным, при клавиатуре нижний отступ --peer-gap. Светлая/тёмная canvas-поверхность и все финансовые цвета прежние. Шрифты и размеры сумм не уменьшались. Структурный layout больше не меняется из-за focus-псевдокласса.

## Остаточные ограничения

- Нативный iPhone/Safari/PWA, аппаратная клавиатура, реальная safe-area и VoiceOver в этой среде не проверены. WebKit/Linux — дополнительный движок, не iOS.
- Полное соответствие Apple Notes по плавному интерактивному скрытию клавиатуры не заявляется. Fallback скрывает её дискретно на верхней границе; сохранение отдельно.
- Нет исходных двух изображений; снимки до/после получены из main и исправленной сборки на синтетических данных. Файлы с keyboard-model используют модель VisualViewport, без изображения настоящей клавиатуры.
- Изменения блоков Главной D1, уведомлений G1, защитных механизмов A1/A2/A3 не выполнялись. Архитектура, финансовая модель, схема, store/crypto/PIN/копии неизменны.
