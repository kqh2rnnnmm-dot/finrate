# P2 — ограничения и открытые вопросы

1. **Настоящий iPhone: OPEN.** Playwright Chromium/WebKit не подтверждают аппаратную клавиатуру, PWA, safe area, системные диалоги «Файлов», менеджер паролей, снимок приложения и выгрузку iOS. A2/A3/P1.1/P1.2 не получают аппаратный PASS вследствие P2.
2. **Единичный A2/WebKit PIN timeout из P1.2: OPEN, причина не доказана.** Исторические доказательства: `Documents/P1_2/OPEN_ITEMS.md` и `Source/evidence/p1_2/`. Новые успешные прогоны не означают исправления того сбоя. Старые проверки не ослаблены.
3. **Личные займы через кредитный счёт: запрещены в P2.** Выбирайте собственный денежный счёт. Кредитная модель B1 не покрывает безопасно все четыре loan/repayment-класса; она не изменялась. Кредитные долги автоматически не превращаются в личные.
4. **Внешний перевод «Другому человеку» не переклассифицируется.** Комиссия, расходная классификация, split/refund и старые отчёты требуют отдельного решения. Для ранее возникшего долга есть создание без движения; исторический расход остаётся расходом. Проверенная привязка доступна только для действующих несвязанных `loan-*`/`repayment-*` без pending/stage, вторичных reference и категорий/распределений, в согласованных сумме/дате/направлении. Остальные исторические записи не преобразуются автоматически.
5. **Прощение/списание/безнадёжность не утверждены.** Нет скрытого обнуления или нового расхода; открытый долг нельзя спрятать архивом. Нужны отдельные правила владельца. Отдельное удаление/обнуление ошибочно созданной открытой карточки старого долга не добавлено: доступны явные исправления условий, а безопасная отмена такой карточки с аудитом требует отдельного решения. Отменённый исходный заём сохраняет карточку с состоянием «Исходная операция отменена» и не маскируется как погашенный.
6. **Совпадение не доказывает тождество.** Проверка ищет равные неоплаченные суммы и сроки (для кредитки — сумму сроковых лотов; при отсутствии срока — общий кредитный долг). Различающиеся оценки, даты и смысл нельзя надёжно объединить автоматически. Владелец должен сверить записи; явное «Это другое обязательство» означает раздельный учёт. Дублирующую сущность не создавайте. P2 не предлагает удалить уже возникшее обязательство или простить его вместо исправления.
7. **Личные возвраты подтверждаются по одному.** Групповая оплата P1.2 остаётся группой обычных расходов. Личный долг открывает собственную форму и сохраняет repayment-тип.
8. **Обратная совместимость односторонняя.** P2 читает P1.2 без записи; старый код P1.2 не рассчитывает и не валидирует P2-долги, а его A2 обнаруживает неизвестный корень. Не используйте старую сборку с новой базой как откат. Кодовая точка d1a415a не возвращает финансовое состояние; нужен проверенный внешний файл до P2 с осознанной заменой данных.
9. **Черновик требует явного сохранения.** Нет обещания пережить принудительное завершение iOS до сохранения. Новый/возвращённый долг и деньги меняются только после успешной атомарной записи.

Суммы подчиняются прежнему безопасному целочисленному диапазону. P2 дополнительно проверяет общий непогашенный остаток каждого направления: слишком большой итог отклоняется до записи, а не округляется.

Проценты, штрафы, графики займов, цели, резервы, лимиты, отчёты, облака, OCR, банки и биометрия не реализовывались. Публикация и merge требуют отдельного согласия владельца.
