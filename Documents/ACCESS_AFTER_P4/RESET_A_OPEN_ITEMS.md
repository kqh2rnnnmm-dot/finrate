# ACCESS-after-P4 A — ограничения и риски

Рабочая ветка codex/access-emergency-reset; access-emergency-reset01 /0.3.15-access-a. Не слито и не опубликовано. Основа e7b3f631187b16b7b01fc49cb975968a2439f93c.

- **Настоящий iPhone Safari / Home Screen PWA: OPEN.** Playwright WebKit/Linux не является iPhone. Нативные «Файлы», share/download, AutoFill и системная клавиатура/VoiceOver/снимки переключателя приложений требуют устройства. Ранее отложенные A2/A3/P1.1/P1.2/P2/P3/P4 и старый A2/WebKit PIN timeout остаются OPEN; успех этого прогона не доказывает исправления старого нестабильного сценария.
- Человек с физическим доступом к экрану может получить шифротекст и явно удалить текущую локальную базу. Это утверждённая владельцем модель, не аппаратная авторизация. Export облегчает офлайн-атаку на слабый пароль. Он не раскрывает DEK/ключ/recovery/PIN/document, не снимает AES-GCM и не меняет PBKDF2. От человека, управляющего JS/браузером/устройством, клиент не гарантирует защиту от удаления.
- Проверка структуры файла не доказывает его расшифровку или физическое сохранение в iOS «Файлах». Кнопка начинает браузерный download, а успешность системной панели подтверждает человек. Повреждённый, но структурно допустимый шифротекст может быть скопирован без обещания восстановимости. Без старого секрета файл останется закрытым.
- При неизведанной/недоступной IDB, отсутствующей или неидентифицируемой/слишком большой записи автоматического удаления нет и intent не создаётся. Если текущий ограниченный снимок идентифицируем, но сам ciphertext-export не проходит структуру, файл не выдаётся. Отдельный сознательный no-copy путь после предупреждения остаётся доступен; это не «проверенная копия».
- Background/pagehide/bfcache аннулируют процедуру, включая потерянный pagehide при pageshow.persisted. Начатая явная транзакция даёт только целиком commit либо rollback; выполнение кода/таймеров при закрытой iOS PWA не гарантируется. При ошибке одноразовая попытка не повторяется автоматически, нужна новая процедура.
- BroadcastChannel передаёт только dataset. Foreground/focus/poll проверяют IDB при пропущенном канале; сохранение независимо защищено CAS. Мгновенную доставку в замороженную вкладку или удаление данных **другого** Safari/PWA-контейнера не обещаем. Privacy CSS не является гарантией контроля снимков iOS.
- Это логическое удаление записей FinRate из vault/safety, а не физическое стирание носителя, Keychain или данных других сайтов. Public SW/cache остаются для обычного первого запуска офлайн; финансовые данные и секреты в shell-cache не сохраняются.
- Кодовый откат на базовый SHA/прежнюю ветку не восстанавливает удалённое финансовое состояние. Для возвращения старой базы нужен внешний файл и **старый** пароль/recovery. При сознательном продолжении без копии/секрета данные могут быть утрачены навсегда. Резервную кодовую точку перед будущим merge следует создать отдельно; текущий PR не объединяется.
- npm audit сохраняет прежние3 low +4 moderate dev/build advisories, high0/critical0; force-fix не выполнялся. Пустые GitHub Actions/commit statuses и CodeRabbit skipped не считаются PASS.
