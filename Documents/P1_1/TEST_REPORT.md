# P1.1 — проверка сборки p1-1-payments01

Версия `0.3.10-p1.1`, основа main597b208. Только вымышленные базы, отдельные профили/origin и локальный HTTP-сервер. Публикации нет. Chromium153 и настольный Playwright WebKit26.5 **не являются настоящим iPhone**. A2/A3 аппаратно не подтверждены.

## Автоматические сценарии

`node --test --test-isolation=none --test-reporter=tap tests/*.test.mjs` — итог сохраняется в [unit.log](../../Source/evidence/p1_1/regressions/patch-unit.log).

- Детерминированные once/weekly/monthly/yearly; 28/29/30/31, високосный февраль, переход года и неизменность исходного якоря.
- Запросы старого документа ничего не материализуют; повторные запросы/периоды не дают дубликатов.
- План не меняет фактические деньги. Части/полная оплата, одна операция/ссылка, повторный requestId, положительность/безопасный диапазон, запрет переплаты и будущей фактической даты.
- Исправление/отмена исходного расхода вычисляет остаток; будущий шаблон не переписывается. Split/категории и удаление соответствующего черновика после записи.
- Будущие версии сохраняют возникшие/досрочные снимки; пауза и возобновление не начисляют пропущенное задним числом.
- Прогноз текущего месяца/2/3/4 месяцев и «Все долги»; дебетовый расход/остаток и кредитное обязательство не вычитаются повторно.
- Неизвестные версии/даты/ссылки отклоняются; CAS и quota rollback сохраняют предыдущий vault/document. Явный повтор после снятия причины записывает ровно один факт.
- Три режима A2 очищают payments; частичные сохраняют защиту, полный удаляет её по прежней политике. Внешняя копия восстанавливает документ полностью в отдельном хранилище.
- Смена основного пароля/PIN, вход по PIN и открытие файла новым паролем/recovery сохраняют операции/платежи. Старый пароль к новой копии не подходит.

## Браузерный сценарий P1.1

Драйвер [payments-browser.mjs](../../Source/tests/payments-browser.mjs) в каждом движке выполняет девять групп:

1. Реальная UI-цепочка существующих редакторов названия/суммы/категории/счёта → создание плана без списания; контекстный поиск.
2. Частичная оплата с двойным submit → одна операция/ссылка и один рост generation.
3. Исправление/отмена через прежнюю карточку факта, восстановление остатка.
4. Native IndexedDB quota на записи active → прежний vault и открытая форма; явный повтор.
5. Полная оплата и отображение canonical истории, включая явную пометку отменённой записи.
6. Существующее контекстное меню, бессрочная пауза/возобновление, пропуск февраля, исходное 31-е марта.
7. Три списка × семь размеров × четыре сочетания темы/палитры; 320px крупный текст, снимки штатного редактора, возврат с принятой защитой несохранённого ввода.
8. Скачивание настоящего защищённого файла, независимое восстановление через native File input и экран подтверждения; полное равенство документа.
9. Холодная загрузка/unlock из service worker без сети, неизменность сохранённого vault.

Размеры: 320×568, 375×667, 390×844, 402×874, 430×932, 844×390, 1280×900. Итого по 84 проверки горизонтальных границ представлений на движок; крупный текст — в каждой из четырёх комбинаций. Готовые редакторы дополнительно покрывает прежняя общая регрессия форм/поверхностей.

Chromium использует context.setOffline(true). В WebKit сервер отказывает всем HTTP-запросам профиля по отдельной cookie: это проверка service-worker загрузки при сетевом отказе, **не iPhone «Авиарежим»**. Флаг setOffline в этом WebKit нарушает native File IO, поэтому его нельзя выдавать за доказательство iOS.

Результаты: [Chromium](../../Source/evidence/p1_1/chromium-payments.json), [WebKit](../../Source/evidence/p1_1/webkit-payments.json), [снимки](SCREENSHOTS.md).

## Диагностические FAIL и ограничения

[red-integration.tap](../../Source/evidence/p1_1/red-integration.tap): до подключения expense seam/A2 allowlist пять ожидаемых отказов (3 forecast, 2 unknown root); после подключения адресные 44/44 прошли. Это реальные промежуточные результаты, не итоги сдачи.

При отладке браузера обнаружена и исправлена привязка нового pause-confirm к кнопке возврата. Остальные ранние отказы драйвера: отсутствие change-события month в WebKit, попытка возврата из страницы как из dialog, неучтённый штатный guard и попытка навигации до завершения export. Исправлены ожидания/маршруты драйвера без ослабления финансовых assertions. Два промежуточных release запуска остановлены перед пересборкой FAQ и удалением лишней подписи в старом списке доходов; они не засчитываются как финальный release.

В обычной sandbox Node запускает дочерние test workers с EPERM, поэтому использован `--test-isolation=none`. Локальные browser/server процессы запускались с разрешённым доступом; приложение никуда не публиковалось.

[Ограничения](OPEN_ITEMS.md): решение о превышении переменного ориентира, P1.2 и аппаратная приёмка не закрыты. Локальные тесты не подтверждают системную клавиатуру, safe area реального устройства, OS AutoFill, физическое сохранение «Файлы», фоновые снимки и аппаратный режим офлайн.
