## Структура и безопасность

Реализована optional payments.version1 внутри существующего зашифрованного документа: планы с версиями будущих условий и интервалами пауз; снимки возникших/оплачиваемых экземпляров; ссылки на существующие операции. SCHEMA5 и IDB/форматы слотов сохраняются, как для уже существующего optional planning. Чтение не материализует и не записывает экземпляры. При первой оплате/изменении условий создаются только необходимые снимки.

Идентичность — planId + исходная календарная дата. Плановая дата и actual date независимы. История оплат — canonical operations, не второй ledger; суммы связей не дублируются. При исправлении суммы/отмене штатной операции остаток рассчитывается заново. Refund остаётся отдельным B1-фактом и не отменяет исходную оплату автоматически.

Откат кода A3 не умеет показывать эти обязательства/учитывать их в свободных деньгах: **не применять старый UI к обновлённой базе как полноценную P1.1-сборку**. Старый формат сохраняет unknown root при обычном roundtrip; прежний A2 блокирует unknown extension вместо удаления. Обратимый возврат полного состояния — собственная внешняя копия до P1.1, без автоматического сброса или удаления новых данных. Совместимость/точный roundtrip и отказ неподдерживаемой версии проверены автоматическими сценариями; файлы реально восстановлены через штатный UI отдельного профиля.

## Границы

Нет массовой оплаты, месячных пауз, переносов, календарного UI, долгов/резервов/лимитов/облака/биометрии. Погашение кредитки — прежний перевод B1, не новый расход-шаблон. Переменный ориентир и превышение вынесены владельцу; до ответа безопасная часть не допускает превышения без согласованного явного выбора.
