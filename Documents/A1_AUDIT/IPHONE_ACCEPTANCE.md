# iPhone: безопасная приёмка A1, 8 шагов

Это **предстоящая** аппаратная проверка, не выполненная на данном этапе. Использовать только вымышленные данные. Нельзя удалять действующую PWA, очищать её сайт или выбирать замену настоящей базы. Подготовка нового публичного origin в этот аудит не входит; отдельная тестовая публикация требует согласия. Для полной проверки нужны заранее согласованный изолированный тестовый origin/PWA и второй независимый чистый профиль, например отдельное тестовое устройство. Не считать Safari и PWA гарантированно разными хранилищами.

1. В изолированной тестовой базе создать вымышленные счёт, кредитный счёт, расход, перевод, возврат и план дохода; изменить палитру/уведомления. Записать итоги и количество операций. Recovery сохранить отдельно от копии, не в присылаемых скриншотах.
2. «Меню» → «Данные и синхронизация» → «Скачать копию». Вручную выбрать место, затем проверить наличие и ненулевой размер файла в iOS «Файлах». Приложение не может подтвердить это за пользователя.
3. Выбрать этот файл для проверки, сначала ввести неправильный пароль, затем правильный. При ошибке файл/ввод остаются, деньги не меняются; после успешного превью выбрать «Оставить без изменений». Повторить с recovery, снова отменить. Никакой замены текущей базы.
4. В **независимом пустом тестовом профиле** восстановить по паролю, сверить итоги/состав/настройки и перезапустить. На другом заранее пустом тестовом профиле повторить по recovery. После restore должен требоваться пароль/ключ копии, старый локальный PIN не переносится. Не очищать существующий профиль для этого шага.
5. Только в одноразовом вымышленном профиле заменить другую тестовую базу: скачать прежнюю, реально проверить файл, подтвердить и ввести `ВОССТАНОВИТЬ`. Проверить новую базу и страховку прежней. В двух вкладках проверить отказ устаревшего превью после нового изменения.
6. После успешной загрузки оболочки включить авиарежим, закрыть и снова открыть тестовую PWA, войти и проверить файл/превью без применения. Затем выключить авиарежим, сверить данные после возврата из фона. Для обновления SW использовать только отдельно согласованную тестовую сборку. Если оболочка тоже потеряна, нужен интернет для начальной загрузки.
7. На вымышленной базе сменить пароль: старый файл проверяется старым паролем, новая копия — новым, recovery сохраняется. Не трактовать это как отзыв старого DEK. Заблокировать приложение: финансовые данные и секреты не должны оставаться на экране; не отправлять скриншоты с секретами.
8. После исправлений этапа 2 отдельно проверить большой заранее подготовленный вымышленный файл, Safari и Home Screen PWA, системное сохранение/выбор файла и прерывание возвратом из «Файлов». Сейчас F01/F06 ещё существуют; не считать их устранёнными. Реальную нехватку места и внезапное выключение не имитировать на рабочем телефоне с настоящей базой.

Результат записывать отдельно для Safari и PWA: модель iPhone, версия iOS, дата, сеть, шаг, ожидаемый/фактический исход. При ошибке остановить применение; исходный файл и действующие данные сохранить.
