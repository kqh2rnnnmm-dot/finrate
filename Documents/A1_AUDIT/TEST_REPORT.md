## Воспроизведение для разработчика

Команды из `Source`, с уже установленными зависимостями. Пользователю выполнять их не требуется.

```sh
node --test --test-isolation=none --test-reporter=tap tests/vault.test.mjs tests/security.test.mjs tests/session-policy.test.mjs tests/b1-integration.test.mjs
node tests/a1-audit.mjs
node tests/a1-browser-audit.mjs
node tests/navigation-upgrade-browser.mjs
npm audit --json --ignore-scripts
npm audit --omit=dev --json --ignore-scripts
```

Браузерные тесты требуют локального loopback-сервера и Chromium; исполняемый файл выбирается существующим `tools/browser-runtime.mjs` (можно задать `FINRATE_CHROMIUM`). Ничего не публикуется. Новый browser audit обслуживает только 7 неизменённых `dist`-файлов и тестовый модуль `/_a1/harness.mjs`, собираемый **в памяти**, для инъекции отказов/гонок через реальный service/store. Этот модуль не входит в приложение или service-worker cache. Все формы восстановления, подтверждения, экспорт и финансовый UI используются из действующей сборки.

Новые тесты намеренно диагностические: процесс завершается с ошибкой при TEST_ERROR; известный воспроизведённый FINDING записывается как находка, а не скрывается зелёным assertion. После отдельно утверждённого исправления понадобятся проверки ожидаемого нового поведения.

## Объём и ограничения

- Node использует одноразовые уникальные имена fake IndexedDB; браузер — новые непостоянные профили, локальный origin `127.0.0.1` и только вымышленные документы. Реальная база пользователя не читалась, не очищалась и не заменялась.
- Пароли/recovery/PIN генерируются при прогоне; в артефактах только ID сценариев, размеры, статусы и обезличенные факты. Реальный browser download читается из временного каталога в память, проверяется и удаляется вместе с временным профилем; файлы копий, сырые ключи и дампы БД не включены в репозиторий.
- F01 получен управляемым повреждением одного символа шифротекста только в одноразовом хранилище. Это не утверждение, что обычный экспорт всегда повреждён.
- F02 проверен с явно заданными условиями: старая копия, её секрет и доступ к новому шифротексту. Старый пароль сам по себе отвергается новым password-slot.
- F06: размер валидного plaintext увеличен тестовым полем `auditPadding`, допускаемым текущим валидатором; это не реальный пользовательский дамп. На 4 194 829 и 8 000 525 байтах экспорт и повторное открытие падают RangeError в Node и Chromium, хотя предел 8 388 608. На 66 061 и 2 097 677 байтах оба действия проходят. Точная граница и WebKit не установлены; резервирование «до 8 МиБ» сейчас недостаточно подтверждено.
- Browser B04 выбрасывает QuotaExceededError после записи active/страховки, на удалении device-access. Native IDB откатывает всю транзакцию. Node дополнительно испытывает отказ до safety.add и active.put. Это инъекции, а не заполнение реального диска.
- B06 останавливает WebCrypto decrypt до перезагрузки; B07 держит транзакцию открытой и уничтожает страницу. Наблюдался полный rollback. Физическое отключение питания, авария ОС и поведение iOS storage eviction не моделировались.
- SW upgrade тест проверяет 15 имеющихся исторических fixtures, вплоть до B1. У его старых подписей осталась строка «→ C1», но текущий assertion действительно проверяет `g1-theme01` в доставленном скрипте. В evidence явно сохранён этот факт; отдельного fixture непосредственного D1 в существующем runner нет.
- Offline подтверждён при сохранённом кэше оболочки и пустой базе. Если исчезли и оболочка, и база, сначала нужен интернет, затем файл/секрет. Нельзя обещать полностью холодную установку из одного файла backup без приложения.
- Повторная сборка не выполнялась: исследовались готовые 7 файлов G1 и соответствующий main. Код приложения, package/lock, build-tool и корневые публичные файлы защищены SHA; новые файлы тестов/отчётов в эти 72 не входят.

## Разбор advisory зависимостей

`npm audit` сообщает затронутые узлы дерева, не число независимых эксплойтов. Все 11 — dev/build: workbox-build и транзитивные rollup/plugin-node-resolve, off-main-thread, deepmerge, ejs, filelist, glob, jake, minimatch, fast-uri, serialize-javascript. Само приложение не устанавливает и не запрашивает их во время работы: runtime bundle локальный, CSP ограничивает сеть; основной npm production dependency — Dexie. Workbox precaching/routing, хотя объявлены devDependencies, **встроены в SW**; поэтому один результат `omit=dev` не доказывает безопасность всего доставленного JS.

Сборка использует `injectManifest`, не шаблонный `generateSW`/EJS; входы сборки — доверенные локальные файлы, не пользовательский backup. Достижимый путь эксплуатации конкретных advisory в установленной PWA этим аудитом не установлен. Требуется отдельная адресная оценка цепочки сборки и совместимых исправлений. Нельзя автоматически применить предложенный npm downgrade Workbox 7.4.1 → 7.3.0 или `audit fix --force`. Зависимости и lock не менялись, новых установок нет. Проверка advisory — запрос метаданных инструментом разработки, не подключение FinRate к внешнему сервису.
