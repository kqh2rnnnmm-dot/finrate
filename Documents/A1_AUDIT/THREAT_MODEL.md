# Модель угроз и границы защиты A1

## Активы и доверенные границы

Активы: целостность/доступность финансового документа; конфиденциальность файла; основной пароль, recovery и DEK; корректное подтверждение замены. Источники доверия: WebCrypto, браузер/ОС, доставленная оболочка того же origin и пользовательский секрет. Это local-first PWA без сервера восстановления и без удалённой страховки. SHA-256 в аудите фиксирует неизменность исследованного кода, не происхождение произвольной внешней сборки.

| Компонент | Фактическая реализация | Граница |
|---|---|---|
| Тело | AES-GCM-256, IV 12 случайных байт, tag по умолчанию 128 бит | Защищает тело и AAD от изменения при неизвестном ключе; не защищает от удаления/отката целиком старого корректного файла |
| DEK | 32 байта getRandomValues, nonextractable CryptoKey, raw-массив обнуляется после использования | JS-строки/копии и память движка гарантированно обнулить нельзя; unlocked context имеет доступ к расшифровке |
| Пароль | PBKDF2-SHA256, 600 000 итераций, соль 16 байт, 12–1024 символа; AES-GCM wrap DEK | Цена перебора, не защита слабого пароля от офлайн-перебора; не memory-hard KDF; не меняется в аудите |
| Recovery | Случайные 32 байта (256 бит), hex, отдельный raw-AES-256 wrap DEK | Ключ вместе с копией даёт полный доступ, пароль не требуется. Хранить отдельно |
| AAD тела | format, datasetId, revision, savedAt; после расшифровки сопоставление с документом | Удалённая копия не имеет внешнего доверенного счётчика свежести. Восстановление старой корректной копии допустимо только явно |
| AAD слота | finrate-key/1, datasetId, type, kdf, iterations, salt | Каждый слот аутентифицируется своим секретом; тело не подтверждает целостность невыбранного слота (F03) |
| Размер/формат | Plaintext до 8 МиБ, input file до 12 МиБ, строгие IV/slot длины/KDF/schema | F06: текущий base64 regexp может раньше лимита упасть с RangeError; F04: null даёт общую ошибку |
| Транзакция | Dexie rw vault+safety, CAS generation+dataset, запись памяти после успешного commit | Контролируемые abort/stale проходят; абсолютная физическая durability при потере питания не доказана |
| Локальный PIN | 4/6 цифр, PBKDF2, device CryptoKey в IndexedDB, счётчик 5 попыток | Быстрый локальный вход, не аппаратная enclave и не независимая защита от злоумышленного кода того же origin. После restore удаляется |
| Service worker | Только оболочка, принятие обновления пользователем, без API-cache/очередей | Не резервирует базу. Потеря всех данных сайта требует снова загрузить оболочку онлайн |

В 13 последовательных шифрованиях IV различались. Это ограниченная проверка вызовов генератора, не доказательство невозможности случайной коллизии. Алгоритм/формат/параметры не менялись.

## Сценарии угроз

- **Утерян локальный профиль / удалена PWA.** Отдельный целый файл плюс действующий при создании пароль или recovery позволяют восстановиться. Если нет ни файла, ни локальной базы, восстановить нечего. Safety в том же origin исчезает вместе с ним. iOS не обещает вечного хранения IndexedDB/Cache Storage; приложение не вправе обещать обратное.
- **Скопирован зашифрованный файл.** Без секрета остаётся подбор пароля; размер, формат, datasetId, revision и время контейнера открыты. Имена/операции/суммы остаются внутри шифротекста. Отдельный файл не становится безопасным при передаче вместе с recovery.
- **Повреждён файл.** В выбранном пути GCM отвергает подмену тела/аутентифицированных метаданных. Структура не заменяет аутентификацию (F01). Повреждение альтернативного слота не обязано обнаруживаться при открытии основным секретом (F03).
- **Старая копия и старый пароль стали известны.** Смена пароля защищает новый парольный slot от старого пароля, но сохраняет DEK. При наличии и нового шифротекста прежний DEK его открывает (F02). Автоматическое пере-шифрование всех старых внешних файлов невозможно. Нужен осознанный выбор политики отзыва; архитектурную смену не выполнять без отдельного решения.
- **Компрометирован разблокированный браузер, same-origin script или ОС.** Может читать документ, использовать CryptoKey, влиять на UI/счётчик PIN; nonextractable не запрещает использовать ключ. Шифрование хранения не решает этот класс атак. Биометрию, усиление входа A3 и новые сервисы в A1 не разрабатываем.
- **Отказ записи / устаревшая вкладка.** Проверенные транзакции откатываются целиком, CAS блокирует перезапись новой версии. Успешная транзакция не является гарантией против физического разрушения носителя.
- **Недоверенный JSON / очень большой файл.** Размер проверяется до чтения; расшифрованная модель валидируется, unsupported format/schema не принимаются произвольно. F04/F06 требуют адресного усиления обработки входа. Самовольно увеличивать лимиты нельзя.

Чувствительные значения генерируются на каждый тестовый прогон и не включаются в evidence. Не публикуются копии баз, recovery, пароли, PIN, raw keys, дампы IndexedDB или секретные скриншоты. Проверка npm advisory ограничена зависимостями сборки/рантайма и не подключает приложение к внешним API.
