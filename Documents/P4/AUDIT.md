Решения для реализации: один месячный rule на categoryId/period, archive без удаления; прошлые периоды отдельно, повторения/перенос нет. Родитель/ребёнок имеют самостоятельные карточки, Home показывает количество/приоритет состояний, не сумму пересекающихся денег. Настройки earlyEnabled/percent (1–99, default80), состояние reached/exceeded всегда видно. Новые назначения — только существующие expense-категории, «Без категории» не изобретается. Исторические суммы следуют текущей явно исправленной классификации B1; freeze старого состава не обещается.

Физический iPhone и прежние A2/A3/P1.1/P1.2/P2/P3 не имеют аппаратного PASS. Старый A2/WebKit PIN timeout остаётся OPEN. Все данные вымышленные, хранилища независимые. Не merge/deploy/Pages/reset user/secrets; следующий этап ACCESS-after-P4 — только передача требований.

## Выполненные адресные изменения

Новые limits.mjs/limits-ui.mjs подключены к прежним маршруту, Home, общим forms/drafts/search/context/history и G1 feedback. Новая геометрия ограничена [data-limits-ui], прежние CSS побайтно сохранены. В model только validators новой optional-сущности/черновика; старый completedNotification сохранён. В service/store/crypto/устройствах доступа/финансовых движках правок нет. Verify-delivery сверяет63 исходных файла,12 разрешённых изменений/2 добавления,101 прежний test-файл (в5 только текущая build-метка) и SHA будущего ACCESS-контракта.

Реальное P3→P4 обновление семи исходных публичных файлов проверяется отдельным upgrade driver: исходная P3-выгрузка, SW update с явным применением, ciphertext/generation без записи при открытии, первая запись правила в одном поколении, независимый restore старой копии. Probe старого P3 подтверждает сохранение optional root, но отсутствие UI/предупреждений; полноценная обратная совместимость не обещается.

Денежные примеры и последствия исторических возвратов/переклассификации: [FINANCIAL_MATRIX](FINANCIAL_MATRIX.md). Фактические прогоны и сохранённые ранние ошибки: [TEST_REPORT](TEST_REPORT.md).
