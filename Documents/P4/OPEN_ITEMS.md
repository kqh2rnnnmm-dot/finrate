# P4 — открытые вопросы

- **Настоящий iPhone / Safari / установленная PWA: OPEN.** Playwright Chromium и WebKit/Linux, размеры, VisualViewport и browser offline не являются аппаратной приёмкой. A2/A3/P1.1/P1.2/P2/P3 ранее приняты владельцем без устройства; прежний A2/WebKit PIN timeout остаётся известным OPEN, не переименовывается в PASS.
- Доступны явные календарные месяцы. Недельные/годовые/автоповторяемые/переносимые лимиты и финансовый цикл не согласованы, не реализованы. Правило для «Без категории» не создаётся.
- При merge категории с правилами безопасная граница — отклонить объединение до записи и предложить явно изменить назначение всех затронутых правил, включая архивные. Автоматическое объединение пересекающихся правил/их истории требует отдельного продуктового решения. Перемещение подкатегории применяет существующую текущую классификацию; замороженные исторические составы не реализованы.
- Общий утверждённый редактор суммы сохраняет предел12 цифр до запятой. Импортированный больший safe-integer предел хранится/показывается точно и остаётся точным при правке назначения/месяца; изменение такой суммы через редактор ограничено его существующим пределом. Производные суммы могут быть больше safe integer — отображаются точно, не служат запретом операции.
- Уведомления только внутри открытого FinRate после подтверждённого действия текущего месяца; фоновый push и массовая доставка прошлых предупреждений отсутствуют. VoiceOver и реальные клавиатуры проверяются на устройстве.
- `npm audit`: прежние3 low +4 moderate, high0/critical0, dev/build цепочки; автоматический force-fix не выполнялся. Полный исходный JSON сохранён. Пропуск CodeRabbit или отсутствие GitHub Actions не являются PASS.
- Кодовый откат к P3 не откатывает состояние. Старый runtime сохраняет optional limits, но не имеет UI/предупреждений/совместимого partial reset. Нужна собственная проверенная защищённая копия до первого P4-сохранения.

## Следующая отдельная задача: ACCESS-after-P4

Аварийное удаление полностью заблокированной локальной базы без всех секретов и привязка Apple Account / безопасное восстановление собственной базы вынесены владельцем **после P4**. Полный подготовленный [контракт](LOCKED_ACCESS_RECOVERY_REQUIREMENT.md) сохранён побайтно. Apple identity сама не расшифровывает vault; потребуются отдельные решения о копии, ключе, доступе и проверке реального восстановления. Ни Apple/Google/OAuth/облако, ни backend/ключи/кнопки в P4 не добавлены. Нового разрешения на этот этап текущая реализация не подразумевает.
