# P4 — финансовый контракт

База: main `eea169f4605a0afa155ab69c95a867ee39749fda`. Сборка `p4-limits01` / `0.3.14-p4`. Статус: рабочая ветка, готово для ревизии, не слито и не опубликовано.

## Сохраняемые данные

Необязательный `limits = {version:1,rules:[{id,categoryId,period,amount,archived,createdAt,request}]}`. `period` — явно выбранный календарный `YYYY-MM` (0001–9999), `amount` — положительные безопасные целые копейки, `request` — исходный канонический запрос для идемпотентности ID после последующих правок. Не более 3000 правил, уникальные ID, одно активное правило на categoryId/месяц. Известные поля и ссылки строго проверяются. Архивные правила остаются со своей историей. Нет расходных сумм, денежных проводок или второго счётчика трат в корне лимитов.

В уже зашифрованных settings: optional `limitEarlyWarnings:boolean`, `limitWarningPercent:integer 1..99`; отсутствие означает true/80. Незавершённый intent находится в прежнем drafts: `kind:expense`, `limitAction:create|edit`, `limitId`, `limitPeriod` и общие поля формы. Пустой месяц допустим только в черновике, не в правиле. Imported safe-integer предел сохраняет точные копейки при правке назначения/месяца без повторного парсинга суммы.

SCHEMA=5, finrate-backup/1, IndexedDB, DEK/слоты/PIN/пароль/AES-GCM прежние. Первая явная запись — один copy→validate→seal→CAS. Чтение старой P3-базы не добавляет limits и не меняет ciphertext/generation. Изменения и вычисленные снимки состояния входят в прежний зашифрованный activity; эти снимки не являются источником расчёта.

## Единственный источник трат

За фактический месяц берутся действующие expense и внешние transfer по существующему isExpense, минус refund по сохранённым refund-allocations. Cancelled/pending исключены. Внутренний transfer, доход, adjustment, loan-*/repayment-*, план, черновик и виртуальные резервирования не участвуют. Нераспределённую часть/комиссию нельзя приписать категории догадкой. Уже категоризированная комиссия — отдельный канонический expense ровно один раз. Современная saveFact-комиссия без категории таковой и остаётся.

Плоские allocations: прямое назначение родителю + назначения его текущих детей; родительский итог не становится новой аллокацией. Конкретный ребёнок считает только свои назначения. Существующее resolveCategory разрешает старые merged allocation IDs. Category move/изменение распределения применяется по действующей классификации B1, замороженный исторический состав не изобретается.

Внутренние агрегаты — BigInt, без изменения старых totals. Производный итог сверх Number.MAX_SAFE_INTEGER представлен точной строкой копеек и не блокирует действительный расход. Настоящие факты и пределы сохраняют старую safe-integer валидацию. Отрицательная чистая сумма из возвратов показывается честно; progress bar ограничена 0..100%, точные значения рядом не обрезаются логически.

## Уведомления

Только новое подтверждённое foreground-действие в текущем календарном месяце, новая revision/event той же базы и повышение состояния существующего активного правила. Общая G1-очередь и финансовые разрешения; компактная группа до3 названий + количество остальных. Нет покупки из уведомления и нет второго журнала доставки. Изменение порога применяется сразу; settings/создание/правка правил, чтение, рендер, reload, старые месяцы и restore не доставляют исторический поток. После реального снижения и нового пересечения новое сообщение уместно. Отключение early не убирает reached/exceeded из карточек. Никакого push при закрытой PWA.

## Сброс и откат

Все три A2-режима удаляют правила и связанные финансовые intents/activity; financial сохраняет два warning-предпочтения, categories возвращает начальные настройки, all удаляет прежнее локальное хранилище/доступ. Счётчики rules/active/archive точные. Незнакомые partial-reset расширения по-прежнему отклоняются; старый явно полный режим сохранён.

Старый P3 проверен отдельно: сохраняет optional limits при восстановлении, но не показывает их и не предупреждает. P4 не меняет деньги, однако кодовый откат не возвращает состояние или поддержку новых правил. Для полного возврата нужна проверенная своя внешняя копия до первого P4-изменения; финансовые копии не коммитятся.
