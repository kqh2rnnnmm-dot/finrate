# P3 — адресный аудит до реализации

Фактический main 3add5d9c1bf4fe74c46f2609884d8527682aa9e4 совпал с заданием. В сравнении с последним head P2 изменены только четыре документа; P2 merge 4bcb315, версия 0.3.12-p2. Чистая рабочая ветка codex/p3-goals-reserves создана от origin/main. Исходные SHA всех src сохранены в Source/P3_MAIN_BASELINE_SHA256.json. Действующий P2 и прежние пакеты приняты без физического iPhone; A2/WebKit PIN timeout не исправляется этим пакетом.

## Готовые механизмы и точечное подключение

- «Цели» — существующая основная вкладка с заглушкой, goal/reserves — уже известные Home metrics. home-config умеет общий выбор показателя, нужен optional goalId существующей настройки.
- forecast(d,...,{reserves}) уже вычитает суммы резервов и уменьшает неоплаченные обязательства на явное покрытие по ID. Постоянных резервов пока нет; подключаем один дополнительный источник, сохраняем сами формулы пяти режимов. model.available() уже умеет тот же контракт и не требует изменения.
- Факты, категории/split/refund, баланс/кредитные проверки, audit/cancel принадлежат operations/block02/credit. Сервис уже даёт private copy→validate→seal→CAS. Не переписываем их. Использование резерва оборачивает существующую каноническую запись и виртуальное уменьшение в одну мутацию.
- P1.2 имеет устойчивый ID экземпляра и confirmPayment; P2 — ID долга/repayDebt. Их подтверждение при использовании связанного резерва должно оставаться тем же expense либо repayment, без второго факта. Возврат долга не превращается в покупку цели.
- Native source-account balance определяет допустимость нового выделения. Старое выделение может стать непокрытым после независимого разрешённого факта: это предупреждение, не причина переписать факт/молча урезать резерв. Если нельзя доказать покрытие конкретной цели/обязательства на таком счёте, показывается неопределённость и предложение явного освобождения; распределение дефицита не угадывается.
- Целевое использование хранит одну активную связь целой фактической операции; виртуально из её одного резерва расходуется явно подтверждённая часть. Реальные возвраты/правки пересчитывают всю чистую покупку. Несколько целей/резервов на одну покупку и распределение возврата по таким частям — открытое расширение.
- После отмены/возврата историческое использование не исчезает, деньги не возвращаются в резерв автоматически. Недопустимая смена счёта связанного факта требует явного отсоединения связи; это не новая денежная операция и не автоматическое пополнение.
- Завершение/отмена цели сохраняют её и историю. Остаток освобождается виртуально или остаётся самостоятельным резервом только по выбору; прошлые фактические траты остаются связаны с целью. Текущий факт и снимок на момент закрытия различаются явно.
- Общие sheet/focus/field-editor/guard/search/context/activity/drafts остаются владельцами UI. Нужны goal/reserve формы и узкие context hooks для использования через существующие редакторы.
- A2 имеет строгую allowlist корней/настроек/плиток. Добавляются только goals и goalId, точные счётчики; частичная очистка с неизвестными полями по-прежнему отклоняется; прежний полный режим A2 и его подтверждения не менялись. Свежий документ A2 удаляет extension по прежним трём режимам.

## Данные и безопасные границы

Optional goals/version1 в прежнем шифруемом SCHEMA5/finrate-backup/1. Goals/reserves и виртуальные события/связи не являются новым журналом реальных денег. Новое выделение — только активный собственный дебетовый счёт, без кредитного лимита/излишка кредитки. Кредитные лоты не являются стабильной поддерживаемой целью покрытия; связь только явная payment/debt. Несовпадение/неопределённость счёта или исчезнувший экземпляр показываются, не исправляются автоматически.

Рекомендация накопления помечена ориентиром; план будущих пополнений/автопереводы не создаются. Это P5. Откат кода по main 3add5d9 не возвращает финансовые данные; понадобится собственная проверенная копия до первого использования P3. Проверка обратного runtime не обещается заранее. Копии, ключи и дампы не публикуются; все тесты — вымышленные отдельные хранилища.

Источник полномочий — прямое задание владельца P3; прежнее «подготовить задание, код ещё не разрешён» в исторических документах не ограничивает текущую реализацию. Продуктовые ограничения и реальные результаты будут отражены в OPEN_ITEMS/TEST_REPORT, без аппаратного PASS.

## Результат адресной реализации

Точечная карта модулей приведена в верхней записи Documents/13_MODULE_MAP.md. Подключены существующие saveFact/confirmPayment/repayDebt, общий UI/история/поиск/черновики и Home config. Новые modules — goals.mjs и goals-ui.mjs; второго денежного движка нет. Source/tools/verify-delivery.mjs проверяет protected modules по исходному main, прежние формулы после снятия только P3 hooks и все старые тестовые assertions (меняется только ожидаемое имя текущей сборки в четырёх upgrade/access-драйверах).

Дополнительный воспроизведённый дефект: прямой app.run скачивания копии выключал кнопки сохраняемого dock, но успешная перерисовка не возвращала им disabled=false. После backup нельзя было нажать Главную без reload. RED в обоих браузерах сохранён в ui-attempt-протоколах; finally точечно освобождает оставшиеся кнопки. Финансовые и защитные механизмы не менялись.

Проверен реальный обратный runtime P2: он сохраняет optional root, но игнорирует резерв в «Свободно». Это не обратная финансовая совместимость. Без проверенной собственной копии до первого P3 rollback не обещается.

Финальная ревизия сохранённых намерений выявила, что typed goal/reserve-поля черновика проверялись по типам, но не по существованию entity. Добавлена только cross-reference validation к существующим draft hooks; сервис по-прежнему владеет атомарностью. Создание нового goal/reserve intent не требует преждевременного создания root. Заметка закрытой цели остаётся read-only в общем viewer, чтобы не показывать недоступное редактирование закрытой сущности.
