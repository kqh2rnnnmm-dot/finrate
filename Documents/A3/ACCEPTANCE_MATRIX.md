# FinRate A3 — обязательная матрица испытаний

Покрыть в Node + Chromium + WebKit/Linux, а отдельно — план iPhone Safari/PWA (не считать выполненным до реального устройства). У каждого сценария фиксировать источник записи, ожидаемый результат, фактический результат, PASS/FAIL/SKIP/DEVICE-REQUIRED и доказательство. До и после каждого опасного действия проверить хеш vault/поколение и итог вымышленной финансовой базы.

| ID | Сценарий | Ожидаемое поведение |
|---|---|---|
| A3-01 | Свежая вымышленная база: основной пароль и recovery | Оба способа открывают базу, чужой пароль нет, копия соответствует полному документу |
| A3-02 | Смена пароля с текущим паролем | Старый пароль не открывает новый vault, новый открывает; финансовые данные идентичны |
| A3-03 | Смена пароля с recovery | Пароль изменён; recovery остаётся доступным; нет ключей в событиях/логах |
| A3-04 | Смена пароля при действующем PIN | PIN сохранён согласно действующей модели; новый пароль и recovery работают |
| A3-05 | Смена пароля при «Открывать без проверки» | Локальный режим и слоты не перепутаны; предупреждение остаётся честным |
| A3-06 | Неверный старый секрет, несовпадение повторов, отмена/Назад | Никаких изменений в active/safety/access, поле очищено после ухода |
| A3-07 | QuotaExceeded/ошибка транзакции, две вкладки, stale | Полный rollback, никакой смешанной защиты, только явный повтор |
| A3-08 | Копия до/после смены пароля | Старая открывается старым секретом, новая новым; recovery и вся финансовая история сохранены |
| A3-09 | PIN 4, PIN 6: установка, вход, смена | Корректный вход, ограниченная длина, скрытые поля, непередача PIN в backup |
| A3-10 | Неверный PIN и лимит попыток | После лимита предусмотренный fallback, успешный reset counters только после входа; деньги неизменны |
| A3-11 | Удаление PIN, повторное включение | Старый PIN не действует, основной пароль/recovery работают, повторное включение задаёт новый PIN |
| A3-12 | «Открывать без проверки» с подтверждением и возврат к паролю | Никакой plaintext базы, явный риск, нет случайного автопрохода при отказе auth |
| A3-13 | Ручная блокировка и autoLock 0/5/15/30/-1 | Условия соответствуют режиму; скрытые формы и поля секретов, безопасный возврат |
| A3-14 | Закрытие/фон во время смены защиты/после скачивания | Нет половинчатых состояний, потерянных подтверждений или ложной успешной записи |
| A3-15 | Restore в независимый чистый профиль | Деньги, копия и пароль восстановлены; старый локальный PIN/none не переносится |
| A3-16 | A2 три режима после настройки PIN/смены пароля | Защита сохраняется в двух частичных режимах; полный удаляет локальные настройки и доступ; только после проверенного внешнего файла |
| A3-17 | Password AutoFill и кнопки show/hide | Без утечки/подмены пароля, доступность iPhone «Пароли», fallback ручного ввода |
| A3-18 | Face/Touch ID: поддержка, отказ, отмена, отсутствие credential | Нет входа без проверенного unlock key; fallback по паролю/recovery всегда остаётся |
| A3-19 | WebAuthn/PRF только при безопасной доказанной реализации | Credential-bound ключ не сохраняется открыто; RP ID/origin/слоты/отмена/смена устройства проверены; если не доказано, UI не включён |
| A3-20 | Обе темы, обе палитры, PWA клавиатура, ПК | Контраст, тексты, кнопки, скролл, отсутствие просвечивания и повторного submit |
| A3-21 | Offline/SW upgrade, повторное открытие | Не требуется сервер для доступа к сохранённой базе; без гарантии фоновой активности PWA |
| A3-22 | Нет утечек в devtools/logs/artifacts/snapshot | Реальные и синтетические секреты не публикуются, логи без raw crypto buffers |
| A3-23 | Неизменность B1.2.1 и schema/crypto/A1/A2/G1 | Точечные hash guards + весь release suite; новые тесты не ослабляют финансовые assertions |

**Критические кейсы на реальном iPhone:** переход Safari ↔ установленная PWA (раздельно); клавиатура PIN и password manager; Face ID/Touch ID/системный код устройства; отключённая биометрия; пользователь нажал «Отмена»; краткий уход в «Файлы»; возврат через 0/5/15/30 минут; восстановление внешней копии в НЕЗАВИСИМОМ тестовом профиле. Не использовать действующую базу для полного сброса и переустановки. Пароли/ключи/PIN не отправлять владельцу или в чат.
