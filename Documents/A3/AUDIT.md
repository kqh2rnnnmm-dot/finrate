# A3 · аудит доступа и адресные исправления

Основа: актуальный main `7abfe0e84442e6b1c8cdf624767ed1341a668473`, PR #7/A2, `a2-reset01`. A2 принят владельцем **без аппаратной проверки**. Ветка A3: `codex/a3-security-access`, сборка `a3-access01`, версия `0.3.9-a3`. Новое [задание](TASK.md) и [матрица](ACCEPTANCE_MATRIX.md) имеют приоритет над историческими статусами. Исторический roadmap R30 отсутствует в repo; использована утверждённая выдержка из [handoff](HANDOFF_STATUS.md).

## Модель угроз и границы

Активы: финансовый документ, пароль/recovery/PIN, DEK и локальный wrapper. Границы: ввод пользователя → временная форма → сервис/WebCrypto → атомарная IDB-транзакция; внешний файл → parse/authenticate → preview → явное применение; другая вкладка → CAS/блокировка; фон → очистка секретных форм/срок сессии. Сетевого сервера доступа нет.

Пароль и recovery открывают разные обёртки одного DEK; PIN/none — отдельная локальная запись `device-access`. Неэкспортируемый CryptoKey не равен Secure Enclave. Код с полномочиями того же origin/доступ к профилю остаётся отдельной угрозой; пять попыток — лимит приложения. Старый файл + его секрет раскрывают прежний DEK, который после смены пароля сохраняется (A1-F02). Ротация не выполнялась. Пароль копии не удаляется при «Открывать без проверки».

## Воспроизведённые дефекты

До исправления `tests/a3-browser.mjs` дал четыре FAIL, `tests/a3-security.test.mjs` — два FAIL (один дефект F05, два способа авторизации). [Исходный браузерный отчёт](../../Source/evidence/a3/chromium-before.json), [красные unit](../../Source/evidence/a3/red-unit.log), [снимки](SCREENSHOTS.md).

- **F01 — фон/секретный UI.** `visibilitychange` только запускал таймер для уже открытого документа; не скрывал поверхности и не отменял секретные формы. Теперь синхронный `access-private` скрывает root, dialogs и сообщения, поля очищаются/маскируются. Секретный процесс закрывается; финансовые формы до автоблокировки сохраняют прежнее поведение. Вход/смена защиты, уже выполняющиеся в фоне, завершаются атомарно и переходят к блокировке. Это не обещание контроля снимков переключателя iOS.
- **F02 — подтверждение с удерживаемым секретом.** Компактное подтверждение none держало замыкание с введённым главным секретом. Чувствительные поверхности помечаются явно; общий стек удаляет их вместе с дочерними подтверждениями при уходе. Замыкание деактивируется, ссылки на значения освобождаются. JS не даёт гарантии физического затирания строк/копий памяти.
- **F03 — смешанный password/recovery и AutoFill.** Селектор способа не очищал текст и состояние show/hide; все поля смены имели off. `access-fields.mjs` задаёт current/new-password только главным паролям, off для recovery/PIN/исторического файла; при смене способа очищает и маскирует. Нет вымышленного username, своего менеджера паролей, credentials.store или авто-submit.
- **F04 — открытая соседняя вкладка.** CAS запрещал запись устаревшей версии, но UI оставался открыт после смены защиты. После подтверждённого security commit существующий BroadcastChannel удаляет финансовый UI соседней вкладки и требует основной пароль/recovery. Канал не передаёт секретов. Сохранён CAS; закрытая/приостановленная ОС вкладка не объявляется мгновенно обработанной.
- **F05 — одинаковый новый пароль.** Прямой сервис и путь recovery принимали тот же пароль и записывали лишнее событие. Проверка выполняется до записи через существующее открытие password slot; новый DEK/формат/история паролей не вводятся. Проверяется совпадение с **текущим**, а не всеми историческими паролями.
- **F06 — невидимый вход после busy-return в WebKit.** При проверке нового фонового жизненного цикла A3 сценарий с удержанной реальной crypto-записью выявил скрытую `.auth` при видимой оболочке после закрытия native dialog. Создание новой auth-поверхности переносится в следующий кадр, после пересчёта видимости оболочки. Это дополнительная проверка изменённого процесса A3, а не заявление о воспроизведении этого случая на исходном main. Красный адресный прогон и последующий WebKit PASS фиксируются отдельно.

**Выявленная и исправленная регрессия разработки.** Промежуточная отложенная отрисовка конфликтовала с немедленным render из persisted-pageshow: первая показанная форма могла замениться и потерять ввод. Это обнаружено существующим history-browser и новым детерминированным тестом [red-pageshow](../../Source/evidence/a3/red-pageshow.log). Один владелец отложенной отрисовки, отмена предыдущего кадра и отсутствие повторного render при pending-frame сохраняют первый ввод. Повторное событие возврата также больше не очищает уже новый ввод; очистка секретов выполняется при уходе. После исправления нужен полный свежий release, результаты прежней сборки не переиспользуются.

После исправлений фактические результаты и ограничения — [TEST_REPORT.md](TEST_REPORT.md). Секретные поля при ошибке основного пароля остаются доступны для исправления, но очищаются при уходе/закрытии; PIN после неверной попытки очищается сразу. Отмена, guard и явное сохранение сохранены.

## Неизменные механизмы

Побайтные SHA-256 guards от актуального main защищают crypto, device-access, store, session-policy, reset-ui/reset-policy, model, operations, credit, planning, block02, recurring-income, SW и все остальные src вне точного allowlist. SCHEMA=5, `finrate-backup/1`, AES-256-GCM/PBKDF2-SHA256/600000, recovery 256 бит, лимиты 8/12 МиБ, CAS и схема IDB прежние. В service добавлена только проверка совпадения пароля. Новых зависимостей и внешних вызовов нет.

Нет изменения заметок, G1 Issue #5, A2-политики, расчётов или дизайна. Открытые границы — [OPEN_ITEMS.md](OPEN_ITEMS.md).
