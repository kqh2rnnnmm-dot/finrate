## Что проверяют A1/A2 регрессии

- Строгий base64, неверный padding/алфавит/размер, старые корректные копии, ровно 8 МиБ plaintext, неправильный пароль/recovery, JSON null/primitive; без увеличения лимитов и смены формата.
- Повреждённый active не выгружается как пригодный и не подменяется памятью. Перед reset проверяется совпадение с фактической записью. Повреждённый body исторической safety сохраняет исходную выгрузку без ложной аутентификации, текущая база не меняется.
- Полная матрица F/C/A: счета/кредит/возвраты/планы/черновики/events/edits, каталог и архив, настройки, slots и device-access. Сохранение PIN/none/пароля; recovery после частичного reset; отсутствие скрытых safety; нулевые totals и все 5 forecast.
- Подделанный/подменённый/отменённый/повторный proof, неправильное подтверждение, wrong secret, lock, stale generation/другая вкладка. Неизвестное расширение блокирует частичную очистку.
- Unit: ошибки active.put и safety.clear; браузер: реальный native IDB abort после active.put, на safety.clear. Оба стора и доступ остаются прежними, UI сохраняет финальную форму, явный retry применяет ровно один переход. Существующий full-reset fault также проверен в combined-browser.
- Фактический browser download → проверка паролем и recovery → нативный File input → отдельное подтверждение → независимая чистая среда. 6 UI-подтверждений паролем и 6 recovery на движок. Копии/секреты в evidence не сохраняются, только SHA и факты.
- Геометрии 320/375/390/402/430 CSS px, 844×390 и ПК 1280×844, обе палитры/темы; root inert за полноценным dialog, нет горизонтального overflow. Сохранены штатные контекстные меню, D1/C1/финансовые/legacy/SW upgrade проверки.

## Офлайн: точная граница доказательства

Chromium: `context.setOffline(true)`, нативный File, три режима, другая вкладка и холодный повторный запуск из SW-кэша.

WebKit/Linux: глобальный флаг Playwright `setOffline(true)` вызывал `NotReadableError` даже при чтении File/Blob; приложение безопасно отклоняло проверку и не удаляло базу. Для отдельной проверки отсутствия HTTP сервер разрывает **все HTTP-соединения** выбранного одноразового профиля по тестовому cookie; незакэшированный fetch действительно падает. Нативный File input/чтение не подменены, `navigator.onLine` остаётся true. По этой модели прошли проверка файла, три удаления, холодный reload кэшированной оболочки и native quota rollback. Cookie существует только в тестах, приложение его не создаёт.

Это модель недоступности сети приложения, **не доказательство режима полёта iPhone**. Реальный локальный/iCloud Files provider, Safari и Home Screen PWA требуют [аппаратной приёмки](IPHONE_ACCEPTANCE.md). Если потеряна и оболочка, для первоначальной загрузки нужен интернет.

## Воспроизведение дефектов и устранение

До правок шесть новых backup-тестов падали; после — PASS. Отдельно воспроизведены прежние низкий toast и сброс translate при отпускании; исходные снимки/JSON сохранены. В ходе A2 пойманы и исправлены скрытый stale login/первый запуск WebKit: устаревший DOM убирается сразу, финальная отрисовка идёт после закрытия modal. Соседняя auth-форма проверена на отсутствие наложения заголовка.

Старые ожидания «уведомление ниже header» и общего текста «Действие не выполнено» обновлены на утверждённое положение и конкретное «Недостаточно места»; проверки rollback, полей, денег и retry сохранены. Проверка отсутствия скачка читает **первый кадр** анимации, а не позднее вычисленное положение после задержки между командами. Медленный недоведённый жест задан явно; быстрый жест вправе закрывать toast.

Скрипты аудита `a1-audit.mjs` описывают прежнюю версию, их исходные FINDING не считаются PASS/результатами текущей сборки. Текущие адресные регрессии — backup-safety/reset-modes и новые A2 browser scripts.
